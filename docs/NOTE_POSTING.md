# note投稿の方針（検証結果と結論）

## 結論（2026-07-18 実機検証）
**note.com への「完全自動投稿（ハンズオフ）」は、正規の手段では実現できません。**
noteは自動投稿を能動的にブロックしているためです。したがって本システムの正式サポートは
**半自動運用**（生成は全自動 → 人が約2分で公開）です。

### 何を試し、何が分かったか
| 試した方法 | 結果 |
|---|---|
| ① 非公式API（Cookieで直接 `POST /api/v1/text_notes`） | **422 で拒否**。画像アップロードも404。トークン(JWT)は30分で失効。 |
| ② ブラウザ自動化（GitHub Actions × Playwright、正規の長期Cookie） | ログインは成功（whoami OK）。だが **noteエディタ自身が起動時に叩く下書き作成 `POST /api/v1/text_notes` が 422** を返し、エディタがローディングのまま描画されない（＝書き込みがbot/CSRF対策で拒否）。 |
| ③ bot検知の回避 | **行いません**（規約・ポリシー上不可。ツール側でもブロックされました）。 |

①も②も同じ `422`。これは note が「自動化されたクライアントからの書き込み」を拒否している強いサインです。
回避（stealth）は規約に反し、かつ note の仕様変更で壊れ続ける“いたちごっこ”になるため、採用しません。

## 正式サポート：半自動運用（確実・規約クリーン）
Claudeルーチンが毎朝、**記事＋高品質サムネ＋note貼り付け用HTML** を生成・コミット・通知します。
あなたは通知を見て、note に貼り付け → 公開ボタン、の**約2分**だけ。手順は [`OPERATIONS.md`](../OPERATIONS.md) §3。

- 生成物：`articles/<日付>-<slug>/` の `article.md`（本文）／`note_body.html`（整形済み）／`eyecatch.png`（サムネ）／`metadata.json`（タイトル・ハッシュタグ）。
- 「毎日1記事」というゴール自体は、この運用で**問題なく達成**できます（＝知識基盤は毎日積み上がります）。

## このワークフロー（`.github/workflows/note-publish.yml`）について
- 参考・将来の再検証用に残しています。**定時実行は無効化**（手動 `workflow_dispatch` のみ）。
- 現状 note がブロックするため、実行しても投稿は成立せず `fallback_package` になります。
- 将来 note が公式APIを出す／仕様が変わった場合に、`scripts/note_playwright_post.py` を起点に再挑戦できます。

## もし将来ハンズオフにしたい場合の現実的な選択肢
- **note公式の予約投稿**：note側の機能で下書きを予約公開（各記事ごとに手動設定。API自動化は不可）。
- **他媒体との併用**：SEO/LLMOの主戦場を、自動投稿APIが使えるCMS（WordPress等）に置き、noteは半自動、という二段構え。
- いずれもご要望あれば設計します。
