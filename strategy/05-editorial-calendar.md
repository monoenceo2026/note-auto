# 編集カレンダー & テーマ選定ロジック

毎日のテーマは「計画（キーワードマップ）× トレンド（根拠）× バランス（クラスタ配分）× カニバリ非該当」で決めます。
このファイルは、そのアルゴリズムと初期の並びを定義します。

---

## 1. テーマ選定アルゴリズム（毎朝、自動実行）

```
1. registry を読み、公開済み primary_kw 一覧と、直近14日のピラー配分を把握
2. keyword-map から status: planned の候補を抽出
3. トレンド分析（§3）を実行し、各候補に trend_score(0-3) を付与
4. 各候補を採点：
     score = priority_weight(4→1) + trend_score + primacy_bonus + balance_bonus
       - priority_weight: priority 1→4pt, 2→3pt, 3→2pt, 4→1pt
       - trend_score:     0-3pt（時事・季節・制度・話題との適合、根拠が言えること）
       - primacy_bonus:   まだピラーが無いピラー配下なら +3（ピラー先行の原則）
       - balance_bonus:   直近14日で少ないピラーなら +1〜2（同一ピラー3連投を避ける）
5. カニバリ判定（§4）で不適格を除外
6. 最高スコアを当日テーマに採用。トレンドで新規スロットを立てる場合は keyword-map に追記
7. 選定理由（trend の根拠・出典）を記事メタとレジストリに記録（「根拠のあるテーマ選定」）
```

### 選定の鉄則
- **ピラー先行**：担当ピラーのピラー記事が未公開なら、原則そちらを優先（土台がないとクラスタが効かない）。
- **同一ピラー3連投禁止**：読者とアルゴリズムの両方に「専門性の広がり」を見せる。
- **トレンドは資産化**：時事ネタでも必ずどこかのピラー/クラスタに紐づけ、単発で終わらせない。

## 3. トレンド分析（根拠のあるテーマ選定）

毎朝、テーマ確定前に以下を **WebSearch** で確認し、候補テーマの `trend_score` を根拠付きで決める。

### 確認する観点（源泉）
1. **制度・政策**：中小企業庁・経産省・J-Net21の新着（補助金、事業承継、賃上げ、価格転嫁、DX/GX 等）
2. **季節・歳時**：展示会/商談会シーズン、決算期、年末年始のEC商戦、インバウンド需要期、ふるさと納税期 等
3. **業界の話題**：製造業DX、AI活用、ライブコマース/TikTok Shopの動向、D2C、事業承継M&A
4. **MONOENの実イベント**：The Lab.の出展（2026/6〜2027/4）、ライブ配信、新規メーカー参加、PR発表
5. **自社検索データ**（将来）：Search Consoleで伸びている/惜しい語（運用開始後に追加）

### 根拠の書き方（記事メタ `trend_rationale` に必須）
- 「なぜ“今”このテーマか」を1〜2文で。可能なら出典（媒体＋年月＋URL）を添える。
- 例：「中小企業庁が2026年◯月に価格転嫁の指針を更新（出典）。価格競争脱却の関心が高まる時期のため P5-001 を前倒し。」
- **裏取りできない“流行っぽさ”だけでテーマを決めない**（AIO時代の信頼性の担保）。

## 4. カニバリ（共食い）判定

新テーマは公開前に必ず判定：

```
NG（採用しない）条件：
  - candidate.primary_kw が registry の published primary_kw と完全一致
  - candidate.primary_kw が既存記事の primary_kw と「同一検索意図」で実質重複
  - 同一ピラー内で intent も対象も酷似（差別化ポイントが説明できない）

一致/近接した場合の対応：
  A. 切り口(intent)を変えて別スロット化（例：費用commercial vs 進め方how）
  B. 既存記事に統合・加筆（新規公開せず既存を強化）→ registryに追記記録
  C. 見送り、次点テーマへ
```

判定は `scripts/registry.py` の `check_cannibalization(primary_kw, intent)` が補助する。
