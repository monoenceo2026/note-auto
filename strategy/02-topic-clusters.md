# MONOEN トピッククラスター設計（ハブ&スポーク）

このファイルは、MONOENのnoteを「ものづくりブランド経営の知識基盤」に育てるための**設計図**です。
毎日のテーマ選定・内部リンク・カニバリ判定は、すべてこの設計に従います。

---

## 0. 設計思想（なぜこの形か）

### ハブ&スポーク（Pillar & Cluster）
- **ピラー記事（ハブ）**：あるテーマの全体像を網羅する“総本山”。ヘッドキーワードを狙う。
- **クラスタ記事（スポーク）**：ピラーの中の一論点を深掘り。ロングテール／検索意図を1つずつ潰す。
- クラスタは必ずピラーへ内部リンクし、ピラーは主要クラスタへ内部リンクする（相互リンク）。
- これにより「テーマの専門性（Topical Authority）」がドメイン全体で積み上がり、**SEOでもAI検索でも“この分野はMONOEN”**という評価をつくる。

### カニバリ（共食い）を防ぐ絶対ルール
1. **1URL = 1プライマリキーワード = 1検索意図**。同じ意図を2記事で狙わない。
2. 似たテーマは「切り口（intent）」で必ず差別化する（下表の *差別化ポイント* 列）。
3. 新規テーマは公開前に**必ず** `registry/content-registry.json` を照合。既存記事とプライマリKWが重複する場合は、
   - (a) 角度を変える、(b) 既存記事へ統合・追記する、(c) 見送る、のいずれか。
4. 上位化を狙う語は**1つのピラー**に集約し、クラスタは補助語（ロングテール）に徹する。

### 検索意図（intent）の型
- `know`（知りたい：定義・仕組み・理由）
- `how`（やり方：手順・チェックリスト）
- `compare`（比較・選び方）
- `case`（事例・体験）
- `commercial`（サービス検討：費用・依頼先）

## 3. 内部リンク設計のルール

1. **クラスタ → 親ピラー** を本文中に必ず1本（文脈に沿った自然な位置で）。
2. **ピラー → 主要クラスタ** を目次的に配置。
3. **隣接クラスタ同士**（例：D2C ⇄ EC ⇄ 販路開拓）を「関連記事」として2〜3本。
4. **異なるピラー間の橋**（例：P5採用課題 → P5採用ブランディング → P4会社の物語）を意図的に張る。
5. アンカーテキストは**プライマリKWそのもの**にしない（過剰最適化回避）。自然な文言＋文脈で。
6. まだ存在しない記事へはリンクしない（`content-registry.json`で公開済みのみ対象）。

## 4. 立ち上げ順序（最初の90日）
