# SEO / LLMO / AIO チェックリスト（note.com 現実版）

このチェックリストは、記事生成とQAガードレールが**機械的に検証**する基準です。
noteは「HTMLヘッダ・meta・JSON-LD構造化データを自分で編集できない」ため、
一般的なSEO手法をそのまま使えません。**noteで実際に効く要素**に絞っています。

---

## 0. note.com の制約を理解する（重要）

| 一般的なSEOでやること | note では | 代替策（本プログラムの方針） |
|---|---|---|
| titleタグ最適化 | 記事タイトル＝titleに反映 | **タイトル設計に全力**（下記1） |
| meta description | 本文冒頭が説明文に自動使用 | **最初の140字を“答え＋要約”に**（下記2） |
| JSON-LD（FAQ/Article） | 挿入不可 | **本文内にFAQ見出し・定義文で疑似構造化**（下記4） |
| 見出しタグ h1-h4 | 大見出し(h2)・小見出し(h3)のみ | h2/h3を論理的に階層化 |
| canonical/内部リンク自由 | 内部リンクは可、canonical不可 | クラスタ相互リンクで代替 |
| alt属性 | 画像キャプションは付くがalt編集は限定 | キャプションで文脈補足 |
| URLスラッグ | 自動(記事キー)で編集不可 | 気にしない（noteの仕様） |

> 結論：**noteのSEO/LLMOは「タイトル・冒頭・見出し構造・本文の情報設計・ハッシュタグ・内部リンク・一次情報」で決まる。** ここに集中する。

---

## 1. タイトル（最重要）

- [ ] プライマリKWをタイトルの**前半**に自然に含む
- [ ] 全角32字前後（検索・SNSで切れにくい）。長くても40字以内
- [ ] 「何が得られるか（ベネフィット）」or「具体性（数字・手順）」を含む
- [ ] 煽り・最上級・釣りにしない（景表法・ブランド毀損NG）
- [ ] 記号は `｜` で区切る程度。過剰な【】や!は避ける
- 例）`製造業のライブコマース完全ガイド｜町工場がTikTok LIVEで語って売る方法`

## 2. 冒頭140字（＝説明文＆AI要約の素）

- [ ] **結論・定義を先に**（逆ピラミッド）。「この記事は何に答えるか」を1〜2文で明言
- [ ] プライマリKWと関連語を自然に含む
- [ ] 「誰の・どんな課題に・何を示す記事か」が冒頭で分かる
- [ ] AIが引用しやすい**自己完結した1文**を冒頭付近に置く（例：「製造業のライブコマースとは、〜である。」）

## 3. 見出し構造（h2/h3）

- [ ] h2は「読者の疑問＝検索クエリ」の形（例：「なぜ製造業と相性が良いのか」）
- [ ] 各h2の**直後40〜60字で“その問いへの直接の答え”**を書き、その後に詳細（AIO/AEOの肝）
- [ ] h2は5〜8個。論理の順序（定義→理由→方法→事例→次の一歩）
- [ ] 目次代わりに、導入直後へ「この記事でわかること」を箇条書き

## 4. LLMO/AIO：AI検索に“引用される”ための設計

- [ ] **定義文**を1つ以上（「◯◯とは、〜です。」）。単語ページ(P7)は特に厳守
- [ ] **数字・具体値**を含む引用可能な一文（出典付き）。例：「配信のゴールデンタイムは朝7〜8時」
- [ ] **一次情報**（MONOENにしか出せる事実）を最低1つ（`00-brand-brief.md`より）
- [ ] **FAQセクション**（h2「よくある質問」＋ h3で Q、直後に短い A）を末尾に3〜5問
- [ ] **要点まとめ**（箇条書き3〜5点）を末尾に。AIが要約として拾いやすい
- [ ] **エンティティの明示**：MONOENが何者か（ブランド創造会社・和製LVMH）を1文どこかに
- [ ] **公開日・更新日・監修者**を明記（信頼シグナル）
- [ ] 出典は「媒体名＋参照年月＋（可能なら）URL」。一次情報・公的情報を優先

## 5. 内部リンク

- [ ] 親ピラーへ1本（クラスタの場合）／主要クラスタへ（ピラーの場合）
- [ ] 関連クラスタ2〜3本（`content-registry.json`の公開済みのみ）
- [ ] アンカーは自然文（プライマリKW完全一致の乱用をしない）
- [ ] リンク切れ・未公開記事へのリンクなし

## 6. アイキャッチ・画像

- [ ] アイキャッチ 1280×670（1.91:1）。テキストは最小限、視認性重視
- [ ] ブランドトーン（無機物×生命／工業×物語）に沿う。実在商品・工程と誤認させない
- [ ] 本文に図解・表を1つ以上（可能なら）。表はテキストでも可（AIが読める）

## 7. ハッシュタグ（noteの回遊・発見に効く）

- [ ] 3〜5個。プライマリKW＋関連（例：#製造業 #ブランディング #ライブコマース #ものづくり #中小企業）
- [ ] ブランドタグを1つ（#MONOEN など）で回遊とエンティティ強化

## 8. コンプライアンス（QAで自動チェック）

- [ ] 禁止ワード（絶対/必ず売れる/業界No.1/古い町工場…）ゼロ
- [ ] `00-brand-brief.md`に無い実名企業・数値を事実として書いていない
- [ ] 景表法（誇大・優良誤認）／薬機法（効能効果断定）に該当しない
- [ ] 出典のない断定的統計を書いていない
- [ ] 競合の名指し批判なし

## 9. 反“ありふれ”チェック（`01-editorial-guidelines.md` §3）

- [ ] MONOEN一次情報・具体手順・当事者視点・独自フレーム・反直感の**3つ以上**を含む
- [ ] 「〜と言えるでしょう」等の定型・同語反復なし
- [ ] どの会社でも書ける一般論だけの段落がない

---

## 10. スコアリング（QAガードレールの合否）

各記事は下記で採点。**合計80点未満、または「必須NG」1つでも該当**なら**自動公開せず「下書き＋警告」にダウングレード**。

| 観点 | 配点 | 必須NG（1つでも×なら公開停止） |
|---|---|---|
| タイトル・冒頭（§1,2） | 15 | — |
| 見出し＆直答構造（§3） | 15 | — |
| LLMO要素（§4） | 20 | 一次情報ゼロ／定義ゼロ |
| 内部リンク（§5） | 10 | 未公開記事へのリンク |
| コンプライアンス（§8） | 20 | 禁止ワード／未確認実名・数値／薬機法・景表法抵触 |
| 反ありふれ（§9） | 15 | 差別化要素が2つ以下 |
| 画像・タグ（§6,7） | 5 | — |
| **合計** | **100** | |
